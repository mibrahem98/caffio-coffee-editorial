# MIZAN COFFEE — Project Operating Instructions

## 1. نطاق المشروع

هذا المشروع هو الواجهة العامة ثنائية اللغة لعلامة **MIZAN COFFEE / ميزان**، وهي تجربة قهوة مختصة تجمع بين قصة العلامة، المجموعة، إرشادات التحضير، النظام البصري، وملاحظات الحقل. تُقدّم الواجهة تجربة شراء تجريبية فقط؛ السلة ومحاكاة الإتمام لا تعالجان مدفوعات حقيقية، ونموذج قائمة الانتظار لا يرسل بيانات إلى نظام خارجي حتى يتم اعتماد تكامل فعلي.

لا يُعاد تقديم المشروع على أنه دليل هوية APEX ROAST ثابت؛ الاسم واللغة والهيكل الحاليان هما مرجع التنفيذ المعتمد ما لم يطلب صاحب المشروع تغييرًا صريحًا.

## 2. ترتيب الأولويات

عند التعارض، يُتّبع الترتيب التالي: صحة الادعاء قبل سرعة النشر، وضوح حالة المنتج قبل الإقناع التجاري، اتساق الهوية قبل إضافة الزخرفة، الوصول والاستخدام على الهاتف قبل التفاصيل الجمالية، ثم قابلية الصيانة قبل الاختصار في الكود.

## 3. قواعد المحتوى والادعاءات

كل معلومة عن قهوة أو مزرعة أو صنف أو معالجة أو ارتفاع أو سعر أو توافر يجب أن تحمل مصدرًا داخليًا أو رابطًا موثوقًا في سجل المحتوى قبل إدراجها في الواجهة. لا يجوز اختلاق مراجعات أو تقييمات أو شهادات أو أعداد عملاء أو نتائج تذوق منسوبة إلى مستخدمين. لا تُستخدم كلمات «معتمد» أو «عضوي» أو «تجارة عادلة» أو «قابل للتتبع» أو ما شابهها إلا بوجود مستند يثبت الادعاء الخاص بالمنتج أو الدفعة.

أي نص تجاري غير موصول حاليًا بنظام طلب أو CRM يجب أن يصف حالته بوضوح على أنها **تجريبية** أو **قيد الإعداد**. لا تُضاف عبارات توحي بوجود دفع أو شحن أو مخزون أو اشتراك بريدي حقيقي ما لم يتم تنفيذ التحقق والتكامل المناسبان.

## 4. الهوية البصرية والتحريرية

الأسلوب المعتمد هو **Quiet Roast Editorial**: توازن هادئ، منشأ قبل الزخرفة، طقس عملي لا وصاية فيه، ودقة دافئة. الألوان المرجعية هي فحمي القمة `#1E2224`، عاجي دافئ `#F2EBDD`، بني التحميص `#4A3025`، ولمسة نحاسية `#B89152`. يبقى DM Serif Display للعرض وManrope للنصوص الوظيفية، مع احترام التباين عند وضع النص فوق الصور أو المساحات الداكنة.

يجب أن يكون المحتوى العربي ترجمة تحريرية كاملة لا تحويلًا آليًا حرفيًا، وأن يطابق اتجاه RTL بصريًا ووظيفيًا. يجب الحفاظ على المصطلحات الأساسية مثل «المجموعة»، «الطقس»، «المصدر»، «المعالجة»، و«ملاحظات التذوق» في جميع نقاط التفاعل.

## 5. حدود التنفيذ التقني

المشروع واجهة ثابتة مبنية على React وWouter وTailwind CSS 4 ومكونات shadcn/ui. تبقى الأصول الكبيرة خارج مستودع الواجهة وتُستخدم عبر مسار التخزين المعتمد للمشروع؛ لا توضع الصور أو الفيديو أو الملفات الكبيرة في `client/public` أو `client/src/assets`. لا تُعدّل `server/` أو مخططات قواعد البيانات أو نقاط API ضمن هذا المشروع ما لم تتم ترقية النطاق واعتمادها صراحة.

أوامر التحقق القياسية هي `pnpm run check` و`pnpm run build`، مع اختبار الواجهة بالعربية والإنجليزية على سطح المكتب والهاتف، وفحص التنقل ولوحة المفاتيح ومسارات الخطأ والروابط والتنزيلات قبل اعتماد أي إصدار.

## 6. بوابة الإصدار

لا يُعتمد إصدار جديد إلا بعد مراجعة النصوص مقابل سجل المصادر، والتأكد من عدم وجود ادعاء تجاري غير مثبت، والتحقق من RTL/LTR، وفحص التباين والتركيز، واختبار حالات السلة وقائمة الانتظار، والتأكد من أن أي مسار غير متصل يشرح حدوده للمستخدم. يجب حفظ لقطة إصدار بعد اكتمال التغيير وقبل إعلان جاهزيته.

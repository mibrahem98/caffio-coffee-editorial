# كافيو كوفي — دليل التسليم التقني والتشغيل

**الإصدار المرجعي:** حزمة Caffio Coffee الحالية. **الغرض:** تسليم تقني منظم للمشتري، وليس دليل تشغيل لمتجر حي أو عقد نقل ملكية نافذ. يجب على المشتري مراجعة هذه الوثيقة مع فريقه التقني والقانوني قبل أي تشغيل تجاري.

## 1. الملخص التنفيذي

Caffio Coffee واجهة قهوة مختصة ثنائية اللغة، عربية/إنجليزية، مبنية كتجربة تحريرية هادئة مع كتالوج منتجات منضبط بالمصادر، وصفات تحضير، بحث ومقارنة، مفضلة، سلة ومحاكاة إتمام محلية، وطبقات مشاركة اجتماعية مولدة من الخادم. تقدم المنصة تفاعلات واضحة دون الادعاء بأن الدفع أو الشحن أو CRM أو جمع البريد يعمل فعليًا.

> **حد التشغيل:** كل تدفق تجارة أو اشتراك أو دفع مرئي للزائر هو محاكاة محلية إلى أن يضيف المشتري مزود دفع وتحقق webhook وسياسة شحن وخصوصية وتنفيذ من جهة الخادم.

| المجال | ما هو موجود في المستودع | ما يلزم قبل التشغيل التجاري |
| --- | --- | --- |
| واجهة عامة | React متجاوب، RTL/LTR، وضع ليلي، انتقالات مسارات، شاشة تحميل، وصول لوحة مفاتيح | مراجعة المحتوى النهائي واسم النطاق وسياسة الخصوصية |
| الكتالوج | سجلات ثنائية اللغة، ملفات تحميص وطرق تحضير، حالات دفعات pending/verified | مستندات المنتج/الدفعات المصدرية لكل ادعاء فعلي |
| التجارة | سلة، خصومات، Society، تتبع وملف محليان | دفع، ضرائب، عنوان، شحن، مخزون، استرداد، webhooks |
| UGC | انعكاسات تذوق محمية ومراجعة مشرف وملخص آلي للتعليقات المعتمدة | سياسة مجتمع، مشرفون، إشعارات، موافقة قانونية واحتفاظ بالبيانات |
| SEO والمشاركة | SSR لصفحات المنتج والمقارنة والتحرير، canonical وOpen Graph وTwitter وصور مشاركة | مراجعة العناوين النهائية وربط domain وrobots/sitemap إنتاجيين |

## 2. المعمارية وتدفق البيانات

الواجهة مبنية بـ **React 19** و**Vite 7** و**TypeScript 5**، مع **Wouter** للمسارات وTailwind CSS 4 وأنماط تحريرية مخصصة. يستخدم الخادم **Express 4** و**tRPC 11** مع **Drizzle ORM** وMySQL/TiDB، ويعالج طبقة OAuth وSSR للبيانات الوصفية والملفات المرئية. تتحكم `ThemeContext` و`CartContext` و`FavoritesContext` في حالات الواجهة، بينما تحفظ المحاكاة غير الحساسة فقط في `localStorage`.

```text
المتصفح
  → React / Wouter / Contexts / typed catalog
  → tRPC (للمصادقة، الانعكاسات، الإدارة، الملخص الآلي)
  → Express + SSR metadata dispatcher
  → Drizzle ORM → MySQL/TiDB
  → Managed storage for static media
```

| الطبقة | المواقع الرئيسية | المسؤولية |
| --- | --- | --- |
| التطبيق | `client/src/App.tsx`, `client/src/pages/` | المسارات العامة، التحميل المؤجل، صفحات العرض |
| المكونات | `client/src/components/` | الرأس، السلة، بطاقات الدفعة، المشاركة، الانعكاسات، المساعد، دليل التحضير |
| منطق العميل | `client/src/lib/` | كتالوج typed، بحث، مقارنة، تجارة محلية، توصيات حتمية قابلة للاختبار |
| الخادم | `server/routers.ts`, `server/db.ts`, `server/comparisonDocuments.ts` | tRPC، الوصول للبيانات، الحوكمة، وثائق المشاركة وPDF المقارنة |
| البيانات | `drizzle/schema.ts`, `drizzle/*.sql` | مستخدمون، انعكاسات التذوق، ملخصات النكهة |
| التوثيق | `docs/` | حوكمة محتوى، QA، تسليم المشتري، تطور المشروع، نطاق SSR |

## 3. كتالوج الميزات ومسارات التطبيق

| المسار | الدور | حالة البيانات |
| --- | --- | --- |
| `/` | تجربة العلامة، المجموعة، مساعد اختيار، دليل تحضير، FAQ، محاكاة شراء | عامة؛ بيانات منتج معلقة عند غياب المستند |
| `/coffee/:id` | سجل المنتج والدفعة ووصفات وUGC معتمد | التذوق والمنشأ لا يعرضان كحقائق إلا عند التحقق |
| `/search` | بحث وفلاتر وفرز وسجل محلي وتوصيات | يعتمد حقول الكتالوج الفعلية فقط |
| `/compare` | مقارنة سجلين ومشاركة وتصدير | لا ينشر إلا حقائق verified أو حالة pending |
| `/notes` | ملاحظات حقل ووصفات | إرشادات بداية وليست وعدًا بنتيجة كوب |
| `/society`, `/track`, `/profile` | محاكاة اشتراك وتتبع وملف محلي | لا بطاقة ولا عنوان ولا شحنة ولا حساب تجاري حقيقي |
| `/payments` | حدود سجلات الدفع | حالة فارغة حتى وصول أحداث مزود موثقة |
| `/admin/tasting` | مراجعة انعكاسات التذوق | محمي بالهوية ودور المشرف من العميل والخادم |

## 4. التثبيت والتشغيل من الصفر

### المتطلبات

يلزم Node.js 22+ وpnpm 10+، وقاعدة MySQL/TiDB فقط عند تفعيل مسارات البيانات المحمية، وحسابات المشتري لمزود OAuth والتخزين وإدارة النطاق. لا تُنسخ ملفات `.env` أو مفاتيح أي طرف ثالث داخل المستودع أو حزمة المشتري.

```bash
pnpm install --frozen-lockfile
pnpm run check
pnpm test
pnpm run build
pnpm start
```

للتطوير استخدم `pnpm run dev`. عند تغيير مخطط قاعدة البيانات: عدل `drizzle/schema.ts`، أنشئ migration، راجع SQL، ثم طبقه في بيئة مناسبة. لا تطبق migration أو تعتمد schema إنتاجيًا بلا نسخة احتياطية وخطة رجوع.

### متغيرات التشغيل

المشروع يعتمد متغيرات منصة للمصادقة وقاعدة البيانات والتخزين. المشتري يضبط القيم داخل مدير أسرار بيئة النشر فقط: `DATABASE_URL`، `JWT_SECRET`، متغيرات OAuth، ومفاتيح مزودات مستقبلية. لا يضم التسليم أي قيمة سرية ولا ينبغي أن يتضمنها.

## 5. واجهات البيانات وAPI

لا يقدم المشروع REST عامًا مخصصًا للعميل؛ تستخدم واجهة المستخدم tRPC تحت `/api/trpc`. تشمل العقود العملية المصادقة، انعكاسات التذوق، المراجعة الإدارية، وملخصات النكهة. يجب اعتبار واجهات الدفع الحية غير موجودة حتى ينشئ المشتري backend ومزود الدفع والـwebhook.

| المجال | الإجراء/السلوك | الحارس |
| --- | --- | --- |
| المصادقة | قراءة المستخدم والخروج | جلسة OAuth من المنصة |
| الانعكاسات | إرسال/قراءة approved/قراءة إدخال المستخدم | مستخدم مسجل؛ النشر pending افتراضيًا |
| الإدارة | صف المراجعة واعتماد/رفض | دور `admin` مفروض من الخادم |
| الملخص الآلي | قراءة ملخص مصدره approved فقط | لا يحل محل سجل المنتج أو الدفعة |
| المشاركة | metadata وPNG/PDF المقارنة | HTML خادمي مقيد بالحقائق المسجلة |

## 6. التشغيل والمراقبة

قبل كل إصدار: شغّل `pnpm test` و`pnpm run check` و`pnpm run build` و`pnpm run test:e2e`. راجع سجلات الخادم والمتصفح وطلبات الشبكة، ثم اختبر سطح المكتب والهاتف وRTL/LTR والوضع الليلي وتقليل الحركة والحالات الفارغة. يبقى فاحص SSR مطلوبًا عند تعديل metadata أو طرق المشاركة.

مؤشرات المراقبة المطلوبة بعد نقل الملكية: أخطاء التطبيق، فشل OAuth، زمن استجابة tRPC، نتائج webhook الدفع، رفض المراجعة، طلبات التخزين، ومعدل فشل صور المشاركة. هذه المؤشرات ليست مفعلة كخدمة مراقبة تجارية ضمن الحزمة الحالية؛ يختارها ويضبطها المشتري.

## 7. قائمة تسليم المشتري

| البند | المالك عند التسليم | ملاحظة |
| --- | --- | --- |
| المصدر وlockfile والتوثيق | وفق اتفاق الطرفين | يتضمن الاستبعادات في manifest منفصل |
| النطاق وDNS | المشتري بعد النقل | يتطلب موافقة المسجل وإعداد HTTPS |
| قاعدة البيانات | المشتري بعد migration ونسخ احتياطي | لا تتضمن الحزمة بيانات عملاء أو تشغيل حي |
| صور وأصول العلامة | حسب تراخيصها المؤكدة | يجب جرد الترخيص لكل أصل قبل إعادة البيع |
| حسابات المزودين | ينشئها المشتري | لا تنتقل أسرار المنصة أو حسابات المطور تلقائيًا |
| حقوق العلامة والترخيص | عقد مستقل | هذا الدليل ليس تنازلًا قانونيًا عن حق |

## 8. انتقال العلامة البيضاء وحقوق الملكية

البنية تسمح باستبدال اسم العلامة والألوان والنسخ والصور والـdomain، لكنها لا تمنح انتقال حقوق تلقائيًا. قبل وصف المشروع كحل علامة بيضاء للمشتري، تحقق من ملكية الشعار، صور التخزين، الخطوط، محتوى النصوص، وسياسات المكونات مفتوحة المصدر. راجع `AR-IP-LICENSE-DRAFT.md` مع محامٍ مؤهل قبل توقيع أي صفقة.

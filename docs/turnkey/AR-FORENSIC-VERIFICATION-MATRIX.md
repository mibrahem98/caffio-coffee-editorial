# مصفوفة التحقق الجنائي والإصلاحات المثبتة — Caffio / MIZAN

**تاريخ الفحص:** 18 أغسطس 2026  
**نطاق الفحص:** واجهة عامة React/Vite ثنائية اللغة، محاكاة تجارة محلية، وطبقة خادم قائمة لم تُعدّل مصادرها في هذه الجولة.  
**المنهج:** إعادة إنتاج العيب أو إثبات حالة الحماية باختبار آلي أو فحص بناء أو مراجعة سجل محددة.

> لا تمنح هذه الوثيقة شهادة «مناعة مطلقة» أو ضمانًا بأن كل جهاز أو متصفح أو تهديد مستقبلي خالٍ من العيوب. وهي تسجل ما فُحص وأصلح وتحقق في تاريخها، مع حدود واضحة قابلة للتصرف.

## ملخص النتيجة

لم يظهر فشل في بوابة الجودة النهائية. اجتازت النسخة **37 اختبار Vitest** و**80 اختبار Playwright**، مع تجاوزين مقصودين لاختبارات hover الخاصة ببيئة اللمس. كما نجح `pnpm run check` و`pnpm run build` و`git diff --check`، وأعاد `pnpm audit --prod` عدادات **0** في critical/high/moderate/low. هذا دليل عملي على تدفقات الفحص الحالية، وليس إثباتًا نظريًا ضد كل هجوم أو عطل ممكن.

| طبقة الإثبات | النتيجة | الدليل القابل لإعادة التنفيذ |
|---|---:|---|
| منطق البيانات المحلية | ناجح | `pnpm test` — 37 اختبارًا، منها حالات Cart/Favorites/Orders تالفة. |
| التفاعل والمسارات والوصول | ناجح | `pnpm run test:e2e` — 80 ناجحًا، 2 متجاوزان عمدًا. |
| الأنواع والبناء | ناجح | `pnpm run check` و`pnpm run build`. |
| التبعيات الإنتاجية | 0 تنبيهات | `pnpm audit --prod --json`. |
| سجلات ما بعد التحقق | لا خطأ متصفح ولا 5xx في نافذة الفحص | مراجعة آخر 160 سطرًا من سجلات الخادم/المتصفح/الشبكة. |
| مسار الأصول | ناجح | `GET /manus-storage/forensic-probe` يعيد 307 بعد إعادة التشغيل. |

## مصفوفة السبب الجذري والعلاج

| الأداة / الوظيفة | السبب الجذري المثبت | الإجراء العلاجي الدائم عمليًا | إثبات منع عودة المشكلة |
|---|---|---|---|
| السلة والطلبات التجريبية | كانت قراءة JSON المحلي تعيد الشكل الخام دون تحقق نوعي؛ يمكن لقيم نصية أو سالبة أو معرفات غير معروفة أن تصل إلى حساب الكمية والحالة. | أضيفت دوال `normalizeCartItems` و`normalizeDemoOrders` و`normalizeFavorites`؛ تسمح فقط بمعرفات الكتالوج، كميات صحيحة 1–99، مبلغ منتهٍ غير سالب، وتاريخ/حالة صالحين. | اختبارات Vitest تغطي JSON تالفًا، كمية نصية/سالبة، معرفًا مجهولًا، حالة خارج النطاق، ومبلغ `NaN`. واختبار Playwright يثبت أن بطاقة السلة تعرض الكمية الصالحة فقط. |
| المفضلة | كانت قيمة `mizan-favorites` تُستخدم كما هي؛ أي مصفوفة غير موثوقة قد تنتج محتوى أو سلوكًا غير متوقع. | التهيئة الآن تزيل العناصر غير النصية أو غير الموجودة في الكتالوج وتلغي التكرار قبل العرض أو الحفظ. | اختبار متصفح يحمّل `alto` و`unknown` وقيمة رقمية ثم يثبت ظهور `alto` فقط. |
| خطاف المصادقة | كان `useMemo` يكتب كائن المستخدم إلى `localStorage` أثناء render، رغم عدم وجود قارئ للمفتاح؛ وهذا أثر جانبي غير لازم وقد يبقي بيانات تعريف محلية. | أزيل التخزين الدائم لمعلومات المستخدم كليًا؛ فصلت حالة الخطاف عن دورة render، وظل مسح token المعاينة في دالة محمية تسجل في التطوير فقط إذا منع المتصفح التخزين. | مراجعة استخدامات المفتاح تؤكد عدم وجود قارئ أو كاتب متبقٍ؛ TypeScript والبناء والاختبارات تعمل بعد الإزالة. |
| حاجز الأخطاء | كان fallback يعرض `error.stack` لكل زائر، ما قد يكشف مسارات أو تفاصيل تنفيذ لا يحتاجها المستخدم. | أصبح العرض رسالة تعافٍ عامة بلا stack؛ تظل التفاصيل في `console.error` داخل التطوير فقط، وزر الاسترداد يستعمل إعادة تحميل صريحة. | اختبار 404 يثبت عدم وجود عنصر `pre` تشخيصي في الاسترداد العام؛ فحص المتصفح لا يسجل استثناء غير معالج. |
| مسار الاسترداد 404 | كان fallback يعمل وظيفيًا لكنه يستخدم بطاقة زرقاء عامة أحادية اللغة منفصلة عن نظام MIZAN، ما يضعف مسار الاسترجاع وRTL/LTR. | أعيد بناء 404 بمكونات MIZAN نفسها: الرأس، اللغة، السلة، رابط العودة، وبروتوكول المصادر، مع `main` قابل للتركيز. | Playwright يختبر الرابط غير المعروف، زري الاسترداد، وعدم تسريب التشخيص؛ مراجعة بصرية سطح المكتب تؤكد اتساق الهوية. |
| إعداد pnpm والتبعيات | كان حقل `pnpm` في `package.json` متجاهلًا من pnpm 10، فتظهر تحذيرات وتصبح تجاوزات/رقعة Wouter غير مضمونة. كما بقي Express 4.21.2 بسلسلة تنبيهات تابعة. | نُقل `overrides` و`patchedDependencies` إلى `pnpm-workspace.yaml` المدعوم؛ رُقي Express إلى 4.22.2 مع body-parser 1.20.6 وpath-to-regexp 0.1.13 وqs 6.15.3. | `pnpm install` بلا تحذير إعداد متجاهل؛ `pnpm why` يعرض النسخ الجديدة؛ `pnpm audit --prod` يعيد 0 في كل الشدات. |
| مسار `/manus-storage/*` | كان السجل التاريخي يحوي `PathError` من تجربة Express 5، بينما المشروع يجب أن يبقى على Express 4 ليتوافق مع wildcard الحالي. | احتُفظ بخط Express 4 المتوافق ورُقي إلى 4.22.2 فقط؛ لم يُطبّق حل يخفي الاستثناء أو يغير صيغة المسار إلى حل غير مثبت. | بعد إعادة التشغيل يعيد probe الحي `307` لمسار asset ولا يظهر `PathError` في الاستجابة أو نافذة السجل الأخيرة. |

## أدوات وحالات تم التحقق منها

تمت تغطية الرأس والتنقل المتجاوب، تبديل الوضع واللغة، RTL، التركيز والتخطي، FAQ وautocomplete، البحث والمرشحات والحفظ المحلي، المقارنة ومشاركة الرابط، سجل المنتج، السلة وكود الخصم والتتبع التجريبي، Society التجريبية، المفضلة، الدفع الفارغ، التقييمات الخاضعة للمراجعة، دليل التحضير، الحركة المخفضة، 404، وتحميل الصور المتجاوبة. وتظل السلة والاشتراك والتتبع والدفع **محاكاة محلية**؛ لا يثبت هذا الفحص وجود بوابة دفع أو شحن أو CRM أو بريد أو تحصيل فعلي.

## حدود متبقية وقرارات بيع آمنة

| الحد | أثره | الإجراء المطلوب قبل الادعاء بعكسه |
|---|---|---|
| لا توجد معاملة أو مزود دفع حي | لا يمكن تأكيد قبول أو استرجاع دفعة، ولا يجوز عرض نشاط محلي كمدفوعات موثقة. | تكامل مزود من الخادم، أسرار محفوظة خارج العميل، webhooks موثقة ومعالجة idempotent. |
| لا توجد دفعات/مصادر منتج تشغيلية جديدة في هذه الجولة | تظل حقائق المنشأ والتذوق والدفعة بحالاتها المصدرية/المعلّقة. | إدخال سجلات قابلة للتدقيق وربط كل ادعاء بمرجع المصدر. |
| 404 عميلة في تطبيق SPA | خادم التطوير يعيد HTML التطبيق بحالة 200 ثم يعرض العميل fallback؛ لا توجد دلالة HTTP 404 مستقلة في نطاق الواجهة. | تعديل طبقة الخادم/النشر لإرجاع حالة 404 دلالية، وهو خارج نطاق الواجهة الثابتة. |

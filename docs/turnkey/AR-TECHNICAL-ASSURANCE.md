# كافيو كوفي — تقرير الفحص الهندسي والأمن التقني

**تاريخ المرجع:** 18 أغسطس 2026. هذا تقرير تدقيق مستودع محدود النطاق، وليس شهادة OWASP أو اختبار اختراق أو ضمان “صفر ثغرات” أو “صفر تسريب ذاكرة”. أي شراء أو تشغيل حي يحتاج فحصًا مستقلًا للتطبيق والبنية والسحابة والمزودات قبل الإطلاق.

## النطاق والأدلة

شمل الفحص هيكل المصدر، الملفات المتتبعة، مسح الأنماط السرية، ملفات الإعداد، تبعيات الإنتاج، المسارات، حدود البيانات، والتحقق الآلي. تم تشغيل Vitest وTypeScript وبناء الإنتاج بعد تحديثات التبعية. فحص التبعيات قبل العلاج أظهر مخاطر متعددة؛ تم تحديث `axios` و`drizzle-orm` و`nanoid` و`streamdown`، وإزالة `recharts` ومكوّن الرسم غير المستخدم.

| فحص | النتيجة القابلة للتحقق | الحد |
| --- | --- | --- |
| ملفات أسرار متتبعة | لم يظهر `.env` أو PEM/KEY متتبع ضمن الفحص | لا يكشف المسح أسرار منصة أو تاريخًا معادًا كتابته خارج git الحالي |
| حوكمة العميل | لا تحفظ المحاكاة بطاقات أو عناوين أو بيانات دفع | المشتري مسؤول عن سياسة الخصوصية والاحتفاظ عند الإطلاق الحي |
| حراسة الإدارة | مسار المراجعة يعتمد OAuth ودور admin من الخادم | يلزم اختبار حسابات المشتري وسياسة أدوارهم |
| تقييد UGC | pending افتراضي، approved فقط للعامة، ملخص آلي من approved | لا يغني عن سياسة اعتدال بشرية أو حماية إساءة متقدمة |
| عرض المشاركة | SSR يقتصر على حقائق pending/verified وسجل تحريري ثابت | يجب اختبار domain النهائي وCDN ومراقبة صور المشاركة |
| اختبارات | 35 وحدة، 76 متصفح في أحدث نقطة تحقق قبل هذا التدقيق | العدد يتغير مع الإصدارات؛ التشغيل النهائي جزء من التسليم |

## نتيجة فحص الاعتمادات

أظهر `pnpm audit --prod` بعد التحديثات المتوافقة **0 critical، و1 high، و2 moderate، و2 low** على 514 اعتماد إنتاجي. الخطر العالي المتبقي يمر عبر `express@4.21.2` و`path-to-regexp` القديم. جُرّبت ترقية Express 5.2.1، لكنها كسرت wildcard قائمًا لمسار `/manus-storage/*` في طبقة المنصة، لذلك أُعيد الإصدار المتوافق لاستعادة تشغيل الخادم بنجاح. لا ينبغي إخفاء هذه النتيجة: ترقية Express الكبرى تحتاج تحديث طبقة التوجيه واختبارًا كاملًا في فرع منفصل قبل اعتمادها.

## الإقرار المهني المسموح

> تم تنفيذ مراجعة مصدر محدودة النطاق وتحديثات تبعية موثقة واختبارات بناء/نوع/وحدة. لا يعني ذلك اعتمادًا رسميًا أو شهادة أمن أو ضمانًا من الثغرات أو التسريبات أو الانقطاع. يجب على المشتري تنفيذ اختبار اختراق ومراجعة بنية ونطاق ومزودات قبل التشغيل التجاري.

## سجل إجراءات ما قبل الإطلاق

1. ترقية Express في فرع منفصل مع تعديل wildcard واختبار SSR والأصول والمسارات.
2. إضافة CSP وheaders وسياسة CORS مناسبة لنطاق المشتري.
3. تفعيل rate limiting وaudit logs وإدارة أسرار ودوران مفاتيح.
4. اختبار اختراق خارجي مع نطاق مكتوب ومعالجة النتائج قبل التعامل مع أي مدفوعات أو PII.
5. تفعيل المراقبة والنسخ الاحتياطي وقواعد الاحتفاظ بالبيانات وخطة الاستجابة للحوادث.
